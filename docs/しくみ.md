# 暮らしクエスト — しくみ

発表用の資料です。何を解いていて、どう作ってあるかを、上から順に書いています。

---

## 1. 解いている問題

引越しの手続きで人が困るのは、**手続きの存在を知らないこと**と、**窓口で出直しになること**の2つです。

```
知らない        「郵便の転送届」「学生納付特例」は、知らなければ調べようがない
出直しになる     持ち物が1つ足りないだけで、その日は終わり。また並び直し
```

いま入っている8件のうち **6件が「知らないと調べようもない」もの**です（データに `littleKnown: true` を付けています）。

検索で解けないのは、**何を検索すればいいか分からない**からです。だから「調べる」ではなく「答える」形にしました。

---

## 2. 全体の流れ

```
  キャラメイク（6問）
        ↓
  ┌───────────┐
  │  抽出      │  その人に要る手続きだけ残す
  ├───────────┤
  │  並べ替え   │  期限順に並べ、前提のあるものを後ろへ
  ├───────────┤
  │  集約      │  同じ窓口をまとめ、持ち物を1枚に
  └───────────┘
        ↓
  窓口の会話（出直しの再現）
```

この3段が `buildBoard()` の中で1回で終わります。画面側は結果を並べるだけです。

---

## 3. 抽出 — その人に要るものだけ残す

キャラメイクの6問の答え（`Profile`）を、手続きの条件（`showIf` / `skipIf`）に当てます。

```
学生ですか？            → 学生でなければ、学生納付特例は消える
マイナンバーカードは？     → 無ければ、カードの住所変更は消える
20歳以上ですか？        → 19歳なら、学生納付特例は消える
ひとり暮らしですか？      → 家族と住むなら、世帯主の届が増える
車やバイクは？           → 原付なら、ナンバーの取り直しが増える
いつ引越しましたか？      → 全部の期限が実際の日付になる
```

### 迷ったら出す

判定は **はい・いいえ・分からない の3値**です（`matchCond()`）。

```
まだ答えていない項目がある  →  消さずに「判定できていない」を付けて出す
```

2値にすると、答えていない人から必要な手続きが**黙って消えます**。消えたことには気づけません。忘れて出直すより、余分に出ている方が害が小さい、という判断です。

条件が複数あるときは、**1つでもはっきり違えば「いいえ」が勝ちます**。そうしないと、要らない手続きが「判定できていません」付きで残り続けます。

---

## 4. 並べ替え — 順番を守る

### 期限は5種類

| 種類 | 例 |
|---|---|
| `beforeMove` | 引越しの1週間前まで（ライフライン） |
| `aroundMove` | 引越しの前後（郵便の転送） |
| `afterMove` | 引越しから14日以内（転入届） |
| `afterProcedure` | 転入届を出した日から90日以内（カードの住所変更） |
| `anytime` | いつでも（学生納付特例） |

`afterProcedure` は、**前の手続きが終わるまで日数を数え始めません**。「まだ数え始めていません」と画面に出ます。

### 前提

```
転出届  →  転入届  →  マイナンバーカードの住所変更
                  →  国民年金の学生納付特例
                  →  世帯主の届
```

前提が終わっていないものには鍵が付き、`orderStops()` が**トポロジカルソート**で順番を決めます。前提のあるものが先に来ることはありません。

**要らないと判断された前提は、待ちません。**カードを持っていない人にとって「カードの住所変更」は不要なので、それを待つ必要はない、という処理を入れてあります（`lock.ignored`）。

## 5. 集約 — 1回で終わらせる

同じ `placeKey` の手続きを1か所にまとめます。

```
学生・家族と同居・原付ありの人（8件）

  1. 前に住んでいた市の市役所  1件
  2. 郵便局                1件
  3. 市役所                5件   ← まとめた
  4. 家（Webか電話）         1件

  出かける回数 3回 ／ 合計 115分
```

家でできるものは、**出かける回数に数えません**。

持ち物も、手続きをまたいで1枚にまとめます。

```
まとめる前  のべ18件
まとめた後  9種
```

「本人確認書類」は6つの手続きで要りますが、**持っていくのは1枚**です。まとめないと、かばんの中身が2倍に見えます。

---

## 6. 窓口の会話 — 出直しを再現する

このアプリの中心です。**知識を渡すだけでなく、失敗を1回させます。**

```
職員「本日はどのようなご用件ですか？」
  ▶ 転入届を出したいです              ← 正解
  ▶ マイナンバーカードの住所も変更したいです
  ▶ 学生納付特例を申請したいです
      ↓ 間違えると
職員「それでしたら、こちらの窓口ではありません」
      ↓ 正しく言うと
職員「住民基本台帳用暗証番号（数字4桁）はお持ちですか？」
      ↓ 家で かばんに入れていなければ
   出直し
```

### 選択肢は、データを増やさずに作る

間違いの選択肢は、**他の手続きの「何て言う」から取っています**（`purposeChoices()`）。同じ場所でやる手続きを優先して混ぜます。本当に紛らわしいのは、そこだからです。

正解の位置は毎回変わります。固定だと、読まずに1番目を押すだけの画面になります。

### 家で入れたものしか出せない

窓口で「持っています」と嘘をつけません。`openBag()` が、**家のかばんに入れたかどうか**を見て答えを決めます。準備画面が意味を持つのは、この一点です。

## 7. 役所の言葉

`officialName`（役所の言い方）と `displayName`（画面の言い方）を組にして、**用語集を自動で作ります**（`buildGlossary()`）。用語データは書いていません。いま **24語**あります。

職員のセリフに役所の言葉が出てきたら、その場で意味を下に出します。

```
職員「住民基本台帳用暗証番号（数字4桁）はお持ちですか？」

この言葉は
住民基本台帳用暗証番号（数字4桁） ＝ カードを作ったときに決めた番号。物ではないので忘れがち
```

---

## 8. 状態の持ち方

持っているのは **2つだけ**です。

```
Profile    キャラメイクの答え（6項目）
Progress   終わった手続き・外したもの・かばんに入れたもの
```

画面に出るものは、この2つと「今日の日付」から**毎回計算し直します**。期限も順番も持ち物も保存していません。**保存した値と計算した値がずれる、が起きません。**

保存先はブラウザ（localStorage）だけです。ログインもデータベースもありません。

### 今日の日付は引数で渡す

ロジックの中で `new Date()` を呼んでいません。サーバとブラウザで結果が変わって画面がちらつくのと、**テストが日によって落ちる**のを避けるためです。

## 9. データと出典

手続きは `src/data/procedures.json` に書きます。**対象は渋谷区**です。

```json
{
  "id": "tennyu-todoke",
  "officialName": "転入届",
  "displayName": "転入届を出す",
  "what": "住民票をこの市に移す",
  "ifNot": "住所が前のままになる。本人確認書類として使えない",
  "deadline": { "kind": "afterMove", "days": 14, "label": "引越しから14日以内" },
  "requires": ["tenshutsu-todoke"],
  "where": { "text": "渋谷区役所 本庁舎3階 住民戸籍課", "placeKey": "city-hall", "verified": true },
  "bring": [ ... ],
  "steps": [ { "n": 5, "text": "...", "stuckIf": { "missing": "juki-pin", "message": "..." } } ],
  "sources": [ { "name": "...", "url": "...", "verified": true } ]
}
```

### 確かめていないものは、確かめていないと出す

値ごとに `verified` を持ちます。**いま22件が未確認**で、画面に「未確認」と出しています。

```
何て言う      8件   実際に窓口で言ってみないと分からない
かかる時間     8件   同上
持ち物        3件   会社や学校によって違うもの
出典         2件   自治体・各社によって違うもの
窓口         1件   前に住んでいた自治体なので、人によって違う
```

隠していないので、「どこまで本物ですか」と聞かれたら**そのまま答えられます**。

### 読み込みで止める

`loadProcedures()` が、壊れたデータを**その場で例外にします**。

```
- steps の stuckIf.missing は、その手続きの bring にある id しか書けない
- requires が循環していたら止める
- 同じ id の重複、順番の重複も止める
- 隠しクエストなのに理由が空なら止める
```

黙って画面が空になるより、早く止まる方がいい、という考え方です。

## 11. テスト

**164件**あります。数字を直接書かず、**データから数える**形にしてあるので、手続きを足しても落ちません。

守っているのは、こういうことです。

```
答えていない項目があっても、必要な手続きを消さない
前提のあるものが、前提より先に来ない
持ち物をまとめても、何のために持つかが消えない
手順に「◯◯を見せる」と書いてあるなら、そこで止まる
用件の選択肢は、正解の位置が毎回変わる
「どちらか一方でよい」持ち物は、片方あれば足りている
```

最後の1つは、実際にあったバグです。学生証の写しを持っているのに「在学証明書が無い」で止まっていました。
